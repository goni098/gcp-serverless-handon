- Keep declarations in the narrowest scope that needs them, such as a module, function, or block. Declarations used only in that scope must stay private or local, with no visibility modifier. Use plain `pub` only for items that need to be accessible outside their defining module. Avoid restricted visibility modifiers such as `pub(crate)`, `pub(super)`, `pub(self)`, and `pub(in path)`.
- Declare shared dependency versions in the root Cargo manifest and inherit them from member manifests. Prefer `default-features = false` and enable only the features the project needs to reduce build times and binary size. [Root Cargo manifest](Cargo.toml)
- When adding an internal crate, choose a name that neither matches nor contains a third-party crate name. Check direct and transitive dependencies in `Cargo.lock` and treat hyphens and underscores as equivalent when comparing names.
  - For tracing, avoid names like `solana-internal`. A `solana` target-prefix filter can match both internal and external targets. Use a distinct internal name and add its exact Rust crate name to the subscriber's [target list](crates/shared/src/tracing.rs).
  - For Cargo Chef, avoid names like `http`. The dependency graph already includes the third-party `http` crate through libraries such as Hyper and Reqwest. A distinct name avoids build target collisions and the risk of recompiling cached dependencies.
- Keep Axum handlers focused on extracting inputs, calling application or repository code, and building responses. Put SeaORM queries in repository modules and models in entity modules. [Example handler](crates/functions/api/src/routes/stats/event_counts.rs) · [Example repository](crates/database/src/repositories/stats.rs)
- Use `app_error::R<T>` for fallible application and repository operations and `shared_function::exception::Rh<T>` for fallible HTTP handlers. Outside Solana program tests, every external crate error type used by the project must have a corresponding variant in `AnyError`. Wrap the original error type with `#[error(transparent)]` and `#[from]` so it can be propagated with `?`. [Application errors](crates/app-error/src/lib.rs) · [HTTP errors](crates/shared-function/src/exception.rs)
- Never call `panic!`, `.unwrap()`, or `.expect()`. Handle failure explicitly or propagate it with `?`. Convert a missing `Option` value to an error with `ok_or_else` when the caller needs to know why it is missing.
- Solana program tests may use `anyhow::Result` and `anyhow::Context` to report failures. Declare `anyhow` as a dev-dependency.
